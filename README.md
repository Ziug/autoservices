# Онлайн-запись для автосервисов

PWA для записи клиентов в автосервис или детейлинг-студию. Каждая студия настраивается отдельно в `tenants/<slug>/business.json`. Примеры `graphite-detailing` и `ceramica-garage` работают в демо-режиме: записи и изменения хранятся только в текущем браузере.

## Запуск

Нужны Node.js 22.13+ и pnpm 11. Для локального предпросмотра:

```sh
pnpm install
pnpm dev
```

Откройте адрес из вывода Vite. По умолчанию корневая ссылка ведёт на `/s/graphite-detailing/`. Без Supabase клиент может пройти пробную запись, открыть кабинет и менять демо-настройки. Это локальные данные браузера, они не отправляют реальные уведомления.

Подключение Supabase, локальный запуск и публикация описаны в [SETUP.md](SETUP.md). Подготовка новой студии за шесть минут — в [CLONE-IN-6-MINUTES.md](CLONE-IN-6-MINUTES.md). Текущий статус проверок и внешние зависимости перечислены в [ACCEPTANCE.md](ACCEPTANCE.md).

## Команды

- `pnpm tenant:new <slug>` — создать демо-профиль студии.
- `pnpm tenant:validate [slug]` — проверить один профиль или все.
- `pnpm tenant:publish <slug>` — синхронизировать профиль, оставив новую студию в preview.
- `pnpm tenant:verify <slug>` — проверить опубликованный профиль и URL.
- `pnpm tenant:activate <slug>` — перевести проверенную non-demo студию в live.
- `pnpm typecheck`, `pnpm test`, `pnpm test:db`, `pnpm test:concurrency`, `pnpm test:e2e`, `pnpm build` — типы, модульные и backend-проверки, браузерный сценарий и production-сборка.

## Безопасность

Публичный клиент содержит только Supabase URL, anon key и VAPID public key. Service-role key, ключ модели и секреты записи задаются только в серверном окружении. SQL-политики ограничивают расписание, платежи и изменения профиля членством владельца в конкретной студии. Публичная запись создаётся транзакционной серверной функцией с защитой от двойной отправки и пересечения времени.
